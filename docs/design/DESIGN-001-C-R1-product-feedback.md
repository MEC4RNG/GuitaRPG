# DESIGN-001-C-R1 — Product feedback and experience refinements

Revision 0.1 — proposed design addendum, not implementation authority.
Parent: DESIGN-001-C, commit 5ac56dc8a8b224bf1c4a3903fc3fe378de2961ce.
Preserve QST-005, JRN-000, EVD/PROG/TRN, all existing application branches and the private-beta gates.

## Home and dashboard
A public visitor sees the public landing/marketing experience; a recognized Player (including an anonymous guest with a valid Player session) sees a personal musician dashboard. Offer guest account protection without blocking valid practice. An active Session takes priority over a new practice action; otherwise resume a recent Journey, offer a justified training recommendation and the always-accessible Quick Quest, recent Workbooks/scores, optional future review and meaningful development insight. New/unknown Players have honest empty states, not fictional ratings. Profile remains account/settings; meaningful Character/development information appears on Home/Skill Map. Avoid treating every metric as a dashboard widget. Test whether different intentions justify layout customization. Route and identity resolution design to be validated; no auth changes now.

## Composer Studio
Design Studio as a distinct first-class creative destination for freely creating, importing, editing and playing compositions independently of Quests or MEC. Craft is a contextual entry to shared musical editing capabilities, not the only way to compose. Workbooks remain the player's organized document/library environment. A score may be created directly in Studio and later referenced/embedded from a Workbook or optionally linked to a Quest. Keep one Player-owned, versioned musical source of truth; no duplicated score copies unless explicitly requested. Exact independent score ownership/reference schema requires an accepted architecture amendment, not implied by JRN-000. Preserve lightweight tab/chord blocks; full score editing provides rhythmic tablature, standard notation, articulations, tracks/voices, tempo, loops, mixing, tuning, import/export and future backing track/audio sync. No required practice or progression updates for free composition. Evaluate whether Studio warrants top-level desktop navigation; mobile via global menu/Workbooks until tested. AlphaTab evaluation MUS-001 remains a candidate: SDK provides score model, SVG/Canvas rendering, MIDI/synth, playback cursor and audio export, not a complete editor or video export pipeline. https://www.alphatab.net/docs/introduction/ ; https://docs.alphatab.net/docs/features/ ; https://docs.alphatab.net/docs/features/export/.

## Creator playback / export (future)
Design a Creator Export view accessible from Studio score playback. Choose whole score/selection, displayed track(s), tab/notation/both, fixed or scrolling/line-following layout, typography/contrast, cursor/highlight, speed/tempo, count-in, aspect ratio/resolution (16:9, 9:16, 1:1; 1080p/4K candidates), opaque solid background or transparent overlay, sound on/off or separate audio. Generate only user-owned/authorized content; respect assets/font/SoundFont rights. Export MP4 for opaque shareable playback, alpha-preserving PNG frame sequence as editing-friendly transparent fallback; evaluate alpha-capable video formats (WebM alpha and ProRes 4444) with target editors before promising compatibility. Use score timing as render clock, including repeats, tempo map, articulations, count-in and selected passage; no screen recording required as final architecture. Verify frame accuracy, A/V sync, alpha compositing, fonts, memory, processing cost, long scores and editor compatibility. Browser vs worker/server export tradeoffs belong to future technical spike. Export settings are presentation presets, not score edits. No media codec or renderer commitment, no new dependency, no launch dependency.

## Workbook and page identification
Identity first, provenance second. Workbook library uses recognizable, compact covers/icons/optional thumbnails, descriptive user-editable title, optional purpose/subtitle, type (e.g. study, composition, reference; proposed presentation taxonomy, not canonical Skill), page count and last updated. Pages use meaningful activity/document titles rather than default Page N when known, ordered position as secondary, content type indicators and optional previews derived from actual text/tab/chord/score blocks. Support list/grid and title/content search, favorites/pins and private labels as future discovery enhancements. No color-only semantics, no decorative cover per page requirement, no artificial screenshot of unseen content. Distinguish explicit linking from automatically suggested related material.
Three separate layers in page header: stable breadcrumb Workbook > Page; current navigation context (Opened from Quest > Explore; contextual return); recorded creation source if reliable, otherwise truthful reference only. Compact expandable association summary when needed, avoid repeated full list. An origin is not a destination or mandatory naming convention. Users may rename material, link/unlink it, find it across contexts without copying. A source marker in editable text is not authoritative provenance. Provenance schema, thumbnails/caching, tags, indexing and content search privacy require separate review. 
Example: Melodic Study (study, 4 pages) > Hear the tonal home (ear-training icon, first note line/short preview), opened from Melodic Navigation > Explore; lesson reference Scale-Degree Recognition; expandable actual linked Quest/skill counts. A standalone composition in Studio may have no Quest, no lesson and no association.

Preserve future spatial computing and advanced learning analytics from B. E prototype may simulate creator export, not generate real music/video.
