## Outcome

JRN-001 implements an isolated, in-memory Workbook Editor prototype at
`/prototype/workbook`. The route is available locally and on non-production Preview deployments;
when `VERCEL_ENV=production`, it resolves through `notFound()` and is not linked from application
navigation. The prototype does not authenticate, call Supabase, persist remotely, or alter Quest,
Journey, Session, Result, Codex, MEC, or progression state.

  and narrow-viewport coverage.

## Document contract

The authoritative interchange shape is `GUITARPG_WORKBOOK_DOCUMENT_V1`, schema version 1. Text,
lists, tablature, and chord diagrams have stable block identities. Tablature events also have stable
identities. Standard and DADGAD snapshots use the accepted low-to-high storage order while the UI
renders high-to-low. Malformed blocks without a recoverable identity fail with an announced error.
Unknown identified blocks are retained as read-only unsupported blocks with their original JSON.
Executable pasted HTML is not retained or executed.

## Prototype capability

- Rich text: paragraphs, three heading levels in the schema, bold, italic, bullet and ordered lists.
- Pages: create, select, rename, duplicate with new block/event identities, and delete in memory.
- Tablature: six strings, fret/open/mute/clear, simultaneous notes, add/remove positions, duplicate,
  Standard/DADGAD tuning, arrow-key cell navigation, touch controls, and an accessible summary.
- Chords: six structured strings, name, fret window, fret/open/mute/clear, tuning snapshot schema,
  finger/barre-compatible data, and a generated textual summary.
- History: text and musical node changes use the same ProseMirror transaction history.
- Serialization: visible export/import/reset controls round trip through the owned schema and never
  transmit data.

## JRN-001-R1 usability remediation

Interactive review identified four presentation and interaction gaps in the first prototype. The
rich-text toolbar read Tiptap state only during React renders, browser list-reset styles suppressed
markers, tablature used a fixed four-column CSS template plus a separate confirmation action, and
the chord editor displayed string lines rather than a conventional fret grid.

The remediation keeps the same document contract and replaces those weak interaction surfaces:

- Tiptap's reactive editor-state subscription now keeps Paragraph, Heading, Bold, Italic, Bullets,
  Numbered, Undo, and Redo state synchronized with selection and transactions. Headings have a
  visible hierarchy, while ordered and unordered list markers and indentation are explicitly owned
  by the editor stylesheet.
- New tablature starts with 16 numbered positions in one non-wrapping grid. Additional positions
  extend the internal horizontal scroller. A focused cell accepts direct one- or two-digit fret
  entry; Backspace/Delete clears it, and the mobile numeric field commits valid frets immediately.
  Open, mute, clear, arrows, identity, order, validation, and unified history remain intact.
- Chords now use six vertical strings and five visible horizontal fret spaces. Clicking an
  intersection places the selected absolute fret directly. Open/mute state, string selection,
  starting-fret label, name, tuning, and notes outside the visible window are explicit. Moving the
  window never rewrites stored absolute frets.
- JSON remains visible in the textarea for round-trip inspection. The display action is named
  literally, and a separate local Download JSON file action is available.

No schema, authentication, persistence, production, or public-traffic change is part of R1.

## Tiptap / ProseMirror assessment

### Evidence

- **Custom React nodes:** React node views support direct editing of structured musical attributes
  without separating music from the surrounding document.
- **Selection and focus:** toolbar commands preserve the document selection; musical blocks expose
  explicit return-to-document controls and predictable Escape behavior. Grid arrow navigation is
  implemented by the GuitaRPG node view.
- **Undo/redo:** musical attribute transactions and rich-text operations participate in one editor
  history and pass mixed browser interaction coverage.
- **Serialization:** an explicit adapter prevents Tiptap JSON from becoming the persistence format;
  deterministic mixed-document fixtures round trip without identity, order, content, or tuning loss.
- **Accessibility/mobile:** semantic controls, generated summaries, visible focus, 44px targets,
  numeric inputs, internal tablature scrolling, axe checks, and the required browser/viewport matrix
  are covered. A future production editor should deepen screen-reader testing of complex grid editing.
- **Maintenance/licensing:** `@tiptap/react`, `@tiptap/pm`, and `@tiptap/starter-kit` 3.32.0 are
  maintained open-source MIT packages. No paid collaboration or version-history package is included.
- **Bundle:** the production build succeeds with the prototype as a separately loaded client route.
  Exact route-level compressed transfer cost is not emitted by the current Next.js 16 build report
  and remains unmeasured; this should be budgeted before production navigation exposure.

### Recommendation

**ACCEPT WITH REMEDIATION.** Tiptap/ProseMirror is suitable for the GuitaRPG-owned structured-block
architecture and should remain the JRN-002 editor foundation if the interactive review passes.
Before production release, add deeper screen-reader/manual keyboard evidence, production-grade chord
barre/finger editing, and an explicit client-bundle budget. Nothing observed justifies implementing
Lexical or direct ProseMirror as a second framework.

## Known limitations

- State is deliberately memory-only and is lost on refresh unless exported.
- Rhythmic notation, measure editing, drag reordering, file import/download, collaboration, and
  revision history are not implemented.
- Finger and barre fields are schema-compatible but have no production-grade editing controls.
- The chord `Clear position` action resets the string to the neutral muted state defined by the v1
  three-state chord contract.
- User visual and tactile acceptance remains outstanding; automation is not visual approval.
- A personal reusable chord library is a future product concept and is not implemented here.
- A reusable note bank for text or musical snippets is a future product concept and is not
  implemented here.
