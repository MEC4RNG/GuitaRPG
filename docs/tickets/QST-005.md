## Accepted direction

The existing immutable resolved Quest remains the musical/practice definition and historical identity. A separate owner-scoped **Quest Journey** overlay tracks saved/open/concluded/archived/abandoned state, current MEC stage, stage activity, and Workspace content using the same Quest ID.

Session remains one bounded practice attempt. Result remains the immutable evidence record for one ended Session. One Quest may have many Sessions and Results. Journey conclusion is explicit Player intent, not mastery or evidence.

MEC is flexible by default: **Map ⇄ Explore ⇄ Craft**. Current Quest families have no strict unlock sequence. `execution.estimated_minutes` is a suggested Session/work-block duration, not total Quest duration.

## Key product decisions

- Save Quest persists without creating a Session.
- Start Quest persists/opens the Journey; Start Practice creates a Session.
- Practice Again creates a new Session against the same immutable Quest.
- Generated drafts use bounded versioned session storage until saved or discarded.
- Home/Generate may show three recent Quests, but the full library has no arbitrary limit.
- Attempted Quests cannot be ordinarily deleted; archive/abandon/reopen remain available.
- Material edits after any attempt create a new Quest identity with optional lineage.
- Quick preserves one-button usefulness; Build progressively exposes existing Custom controls.
- Unsupported Primary Skills are disabled/explained or excluded; never substituted.
- Secondary Skills are developmental lenses; Required Techniques are execution prerequisites.
- Quest Workspace initially contains Journal, References, and later a bounded Quest-aware fretboard.
- Journal and Craft content never automatically becomes Result evidence or progression.
- Protected accounts support refresh-based cross-device persistence; guests receive no recovery/sync promise.
- Realtime, audio/media, tab/notation, DAW behavior, and automatic stage completion are deferred or not required.

## Persistence recommendation

Future implementation should retain `quests` unchanged and add the minimum owner-scoped records:

- `player_quest_journeys` — one lifecycle/read-model row per Quest
- `quest_workspace` — versioned aggregate for bounded fretboard/anchor/Craft state
- `quest_journal_entries` — independently ordered and editable Journal rows

Creative artifacts and fretboard state should not become separate tables until independent multiplicity/query/media requirements justify them. Future writes derive ownership from `auth.uid()`, use RLS, preserve attempted-Quest history, and extend DATA-004 export/deletion and backup/privacy coverage.

## Minimum implementation slice

1. Preserve generated draft through ordinary navigation.
2. Save Quest and Start Quest without Session creation.
3. Add Journey lifecycle and Saved Quests library/read model.
4. Add flexible MEC Journey shell.
5. Surface multiple Sessions and Practice Again.
6. Add contextual Codex Peek.
7. Add basic Journal persistence.
8. Extend export/deletion and integration coverage.

The simple Quest-aware fretboard is the next adjacent slice rather than a prerequisite for the first coherent persistence/UI delivery.
