# PLY-003 — Functional Player Profile Editing

**Status:** IN PROGRESS

## Objective

Replace the Profile placeholder with a Player-owned editor for established practice preferences and active goals, backed by one authenticated atomic save.

## Contract

PLY-003 reuses `player_profiles`, `player_tuning_preferences`, `player_goals`, and canonical `taxonomy_entities`. Editable state is display name, experience background, typical session duration, challenge preference, one default tuning, and active Skill, Domain, or practice-note goals. Calibration and onboarding status are read-only; progression, XP, readiness, proficiency, confidence, Attributes, locale, timezone, setup inventory, account management, and Settings remain outside scope.

The `save_player_profile_v1` RPC derives ownership only from `auth.uid()`, locks the Profile row, validates all canonical references and goal ownership, preserves existing goal identity and priority, assigns priority 100 to new goals, deactivates omitted active goals, and commits profile, default tuning, and goals atomically.

## Training semantics

Fresh Training reads consume the saved challenge preference, typical duration, default tuning, and structured goals. Existing TRN scoring is unchanged: Skill and Domain goals retain their established matching signals, practice notes remain diagnostic only, and unsupported Skills are retained without substitution.
