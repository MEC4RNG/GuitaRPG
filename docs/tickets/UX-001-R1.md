# UX-001-R1 — v1 Navigation Contract Refinement

**Status:** COMPLETE

## Discovered conflict

UX-001 originally defined desktop SYSTEM navigation as Profile and Settings. The later accepted P5-SCOPE-001 launch review found that Settings remains a placeholder with no independently meaningful v1 behavior and decided that it should be hidden rather than artificially implemented. UX-004 could not implement that decision while the higher-level UX-001 authority still required Settings.

## Authorities

- Higher design-system authority: UX-001 — Hybrid Design-System Contract
- Later launch-scope decision: P5-SCOPE-001 — Phase 5 Launch-Critical Scope Review
- This remediation explicitly reconciles those authorities before UX-004.

## Precise amendment

The design-system authority is forward-versioned from `UX_V1` to `UX_V1_1`, retaining schema version 1. Desktop navigation remains:

- PLAY: Home, Generate, Training
- DEVELOPMENT: Character, Skills, History
- LEARN: Codex
- SYSTEM: Profile

Mobile remains Home, Generate, Skills, Profile. Generate remains the universal primary action. No palette, surface, typography, spacing, layout, motion, accessibility, component, or interaction invariant changes.

## Settings disposition

Settings is deferred from exposed v1 navigation until independently meaningful application/settings behavior exists. GuitaRPG must not expose a placeholder Settings destination merely to preserve the earlier information-architecture draft.

UX_V1_1 governs exposed primary navigation. The `/settings` route may remain temporarily in source until UX-004; route existence does not approve Settings as an exposed v1 product surface. This amendment does not prohibit a later real Settings capability.
