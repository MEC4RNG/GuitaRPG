# ONB-001 — Onboarding & Calibration Foundation

**Status:** COMPLETE
**Phase:** 1 — Product Foundation
**Depends on:** DATA-002, TAX-003-R1, PLY-001, PLY-002, PROG-001, UX-001, UX-002

## Objective

Provide a concise, durable first-run Player setup flow without fabricating evidence,
proficiency, XP, Character Level, or Attribute state.

## Authority

- DATA-001 persistence and identity contract
- PLY-001 Player and development-state contract
- PROG-001 progression contract
- TAX-001 taxonomy contract and TAX-003-R1 canonical Tuning Contexts
- UX-001 design-system and UX-002 application-shell contracts

## Scope

- `/onboarding` first-run flow using existing PLY-002 tables
- anonymous Auth uses the same Player model as permanent identities
- Player-authored experience, session preference, challenge preference, tuning, and
  optional goal persistence
- explicit optional calibration choice: future calibration setup or skip

## Non-goals

No Quest/runtime diagnostics, Results/Evidence, XP awards, proficiency calculation,
Attribute derivation, audio grading, account management, or ONB-001 schema migration.

## Implementation summary

The flow marks a bootstrapped profile `IN_PROGRESS`, persists only PLY-002 editable
columns/tables, and marks onboarding `COMPLETE`. Calibration may be `SKIPPED` or
`IN_PROGRESS`; neither route writes any derived Player state. Existing completed
Players are shown a completed state instead of being forced through the form again.

## Acceptance criteria

- first-run setup is reachable and mobile/keyboard accessible
- Player-authored choices persist under existing RLS boundaries
- anonymous Auth receives the same Player model
- self-declared experience creates no proficiency, XP, or Attribute change
- calibration remains optional and does not fabricate an estimate
- returning completed Players are not replayed through setup
