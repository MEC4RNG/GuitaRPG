# JRN-000 — Player-Owned Journal & Workbook Architecture Reconciliation

**Status:** COMPLETE

## Objective

Reconcile the accepted standalone Player-owned Workbook direction with QST-005, existing Quest and
Journey persistence, Codex, Session/Result/progression boundaries, and Player export/deletion
authority without implementing product or database behavior.

## Accepted designation

Player → Workbooks → ordered Pages → versioned structured content blocks is the canonical ownership
model. Quest, Session, MEC stage, Codex/taxonomy, and Player tags are optional associations. Quest
deletion removes only links; account deletion removes the private Workbook graph.

## Key decisions

- One shared editor serves standalone Journal, Explore observations, and Craft composition.
- Editable content uses `GUITARPG_WORKBOOK_DOCUMENT_V1`, not HTML/images as authority.
- Tiptap/ProseMirror is the first prototype candidate; custom React/SVG node views implement musical
  blocks. Lexical remains a measured fallback.
- Tablature stores ordered measures/events, string/fret data, tuning snapshot, and reserved rhythmic
  fields. Chord diagrams store structured string/barre/fret data.
- Owner-derived trusted mutations, RLS, immutable accepted revisions, request idempotency, and
  optimistic concurrency prevent cross-owner writes and silent overwrite.
- Player tags and canonical taxonomy associations are distinct.
- Official Codex records remain immutable; `Your notes` is an owner-scoped discovery projection.
- Workbook activity has no Session timing, Result, evidence, or progression authority.
- QST-008's unimplemented Quest-owned Journal proposal is superseded by the JRN sequence. FRET-001
  retains Quest-aware fretboard scope and must interoperate with the shared block contract.
