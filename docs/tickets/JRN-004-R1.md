## Why this remediation exists

The user reports the JRN-004 context links, shared Workbook workflow, and authentication functioning as expected. **Functionality is provisionally accepted; layout is not yet accepted.** The Journey currently displays one generic Workbook panel above each stage. Explore's practice focus, supporting skills, and techniques are static sections; Craft requires leaving the stage to edit. The requested change is organizational and compositional, not a new Journal implementation.

Do not mark the parent complete or merge PR #13 merely because the original JRN-004 automated gates passed. New changes require fresh final-head validation and user interactive review.

## Agreed product decisions

1. **Explore uses independent expandable/collapsible Skill modules** for the primary skill, supporting skills, and required techniques present in the immutable Quest snapshot. The Player may keep multiple modules expanded simultaneously.
2. **Explore page discovery uses Option 3:** show pages linked to the current Quest + module first, then "Other Workbooks for This Skill" as a secondary expandable area **when true canonical Skill associations are available**. Cross-Quest owner-scoped discovery belongs to JRN-005; do not fabricate it from page titles or Quest-only links.
3. **Explore modules are reorderable by the Player**, starting with accessible Move Earlier / Move Later / Reset to Suggested Order controls; persist the per-Quest presentation order without changing Quest generation, requirements, difficulty, or progression.
4. **Craft uses Option 1:** the **main canvas is the real, editable persistent composition Workbook**, not a link-only panel. The existing right-side Start Practice / Suggested Session area becomes a **contextual Quest Toolkit** with skills, techniques, constraints, creative prompts, and a distinct Start Practice action.
5. **Craft opens the most recently edited eligible composition page linked to this Quest** by default. On a first visit with no eligible composition, offer **New Composition** without silently creating anything. Permit choosing another composition and creating additional pages; use one shared Workbook/persistence authority throughout.
6. On narrow/mobile layouts, keep the editor accessible and offer a focused editing presentation, with a collapsible/accessible Quest Toolkit. No mobile-only data model or editor fork.

## A. Explore — modular practice workspaces

### A1. Structure / interaction

- Render one Skill module per distinct canonical Skill or required-technique reference in the Quest snapshot; primary focus precedes supporting skills, then required techniques in the suggested order. Deduplicate shared Skill identities and display all applicable roles, preserving source/reference context.
- Each module's collapsed header shows canonical display name, applicable role (Primary / Supporting / Required Technique), and **truthful** linked-page count. An expanded module shows the applicable musical/practice guidance, Codex link/Peek, current-Quest linked pages, and New Page / Link Existing controls scoped to that module.
- Avoid inventing a unique objective for each supporting Skill: display the actual Quest objective/role/parameters only where meaningful and source-backed. Keep target tempo and Quest-wide constraints available without fabricating module-specific targets.
- Support multiple expanded modules. Use semantic disclosure buttons with `aria-expanded`, labeled regions, keyboard focus, 44px minimum touch targets, visible focus, and no hover-only actions. Empty states should say no **module-assigned** pages rather than no Quest pages.
- Replace the redundant top-of-Explore generic Workbook strip with module-scoped discovery; retain an honest **General Explore Pages / Unassigned** area for legacy Quest-stage links that have not been assigned to a module. No data loss or automatic reassignment by title matching.
- Keep Map's existing informational layout and optional Workbook access intact; preserve current Explore practice information and Start Practice availability.

### A2. User-controlled ordering

- Implement Move Earlier, Move Later, and Reset to Suggested Order per Quest and Player, with first/last unavailable actions disabled correctly.
- Order must persist after refresh, leaving/reopening the Journey, and protected cross-device sign-in. New/removed Quest snapshot modules must reconcile deterministically without corrupting stored order.
- Store **presentation ordering only**, through an owner-scoped bounded existing mechanism or a minimal additive migration with trusted write/read boundaries. Never mutate the immutable Quest snapshot or create Session/Result/progression events.
- Expansion state can be ephemeral per page visit; it must not accidentally affect persisted ordering or cause editor drafts to be discarded. Drag-and-drop is **not required** for this remediation.

### A3. Module-to-Page context and JRN-005 boundary

- To make **current-Quest** page lists correct, attach the page to the selected Explore module through an explicit, owner-validated, Quest-scoped module identity derived from canonical snapshot Skill/technique references. Persist the association without modifying Workbook page JSON or incrementing page content revision.
- The preferred boundary is an **optional module discriminator on a Quest/stage context edge** (or equivalent narrowly scoped link), not a global Skill-to-Page taxonomy association. Document the precise schema/RPC design before implementation; use only append-only migration(s) if needed, with RLS, `auth.uid()` ownership, bounded validated inputs, and safe cascade/unlink behavior.
- Never infer module membership by matching page title or text. Where legacy Explore links have no module identity, show them as unassigned with an explicit assign/move action. A page may be linked to several meaningful contexts without duplicating content.
- Show current Quest + module pages first. Reserve "Other Workbooks for This Skill" (cross-Quest/global Skill discovery) for **JRN-005**. Until such a trusted, owner-scoped taxonomy association exists, **omit this secondary section or label it plainly as a future capability; do not show guessed pages or dead controls.**
- Do not alter Codex system content or launch an owner-scoped global discovery/index in R1. Ensure JRN-005 can later add the second section without rebuilding the Explore modules.

## B. Craft — composition-first editing

### B1. Main canvas

- Replace the generic Craft Workbook link panel with an **embedded instance of the actual persistent editor** in the main canvas. Reuse existing Tiptap/ProseMirror, tablature/chord blocks, document validation, autosave/concurrency, retained revisions, and page CRUD. **One persistent document authority** across embedded Craft and standalone `/workbooks`; no copied JSON drafts presented as saved compositions.
- Refactor shared presentation/data controller boundaries if necessary to prevent duplicating Workbook hydration, trusted mutations, autosave, or conflict handling. Keep standalone `/workbooks` fully functional; avoid mounting conflicting editor instances for the same page simultaneously.
- Provide a compact composition page selector, New Composition, and Open in Full Workbook Editor. Multiple pages and Workbooks may be linked to one Craft stage; the selected page must be labeled with its actual owning Workbook/page identity.
- Default selection: newest `updated_at` among **owned, accessible, unarchived page(s) linked to this Quest with stage CRAFT**, with stable tie-breaking. Do not accidentally choose a page from another Quest or an Explore/Map-only link. After the user explicitly selects another page during the current editor session, do not override that choice on background refresh.
- First visit with no composition: show a truthful empty state with New Composition; do not create a Workbook/page or link without explicit action. New Composition must select an existing appropriate Workbook or create one with the user's action, then persist the new page and **confirmed** CRAFT association; failures expose an unlinked but recoverable page without claiming it is linked.
- Switching composition pages, leaving Craft, changing MEC stages, going to full editor, and Return to Journey must honor unsaved/pending/conflict handling and cannot silently discard local drafts. Preserve existing revision history and recovery operations.
- Loading an archived/deleted/unowned/missing page degrades safely, shows no unauthorized data, and offers a valid next action without redirect loops.

### B2. Right-side Quest Toolkit

- On desktop, use the existing right-side Journey practice-panel location for the **Quest Toolkit**: primary skill, supporting skills, relevant required techniques/concepts, constraints/tuning/tempo as applicable, and creative prompt suggestions.
- Retain a clear **Start Practice / Practice Again** action within a visually distinct subsection; existing Session lifecycle, archiving rules, and practice panel behavior must remain authoritative. Do not turn editor focus, input, or save events into Session time, evidence, or grading.
- Keep the right panel compact and optionally sticky only when it will not obstruct short viewports, focus navigation, mobile, or the editor. Codex links/Peek remain usable.
- On mobile, stack or disclose the Toolkit without placing a large obstacle before the composition editor; focused editor view must allow comfortable tablature/chord editing. No clipped strings, page-level horizontal overflow, trapped keyboard focus, or loss of draft on mode change.
