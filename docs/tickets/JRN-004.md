## Objective

Connect the existing Player-owned, persistently editable Workbooks and Pages to the Map / Explore / Craft Quest Journey without introducing a second Journal or changing Quest, Journey, Session, Result, or progression authority. A Player can create and revisit a musical note or composition from a stage, find it again from the Journey and standalone Workbooks, and edit it across refresh/device sessions.

## Invariants (non-negotiable)

1. `auth.uid()` owns Workbook → Pages → immutable bounded revisions. Neither Quest nor Journey owns a document. Context links cannot grant access.
2. Existing `GUITARPG_WORKBOOK_DOCUMENT_V1`, SVG musical blocks, autosave, conflict/refusal behavior, undo/redo, and recovery revisions remain authoritative. No editor fork or duplicate Quest Journal.
3. Context associations are **optional**. A Workbook/Page may have no Quest, stage, or Session, and may outlive all of them. Deleting an otherwise deletable Quest/Session removes only link rows, not a Workbook/Page. The existing attempted-Quest deletion guard stays intact.
4. Journey stage navigation is freely revisitable. Viewing/creating/editing/linking a Page does not create or end a Session, change current MEC stage implicitly, create a Result/evidence, or award XP/proficiency/confidence/Attributes/readiness/recommendation weight.
5. Map remains an instructional stage; notes are optional. Explore may capture observations, Craft may persist compositions. A document is not graded by mere presence or editing.
6. No untrusted return URL or cross-owner ID can cause access, mutation, navigation to an external site, or leaked content. Guest/protected Player behavior is preserved.
7. No change to `main`, production traffic, default branch, protected `v1-production`, official Codex content, or release cutover.

## Authorized implementation scope

### A. Player-owned contextual associations

Introduce only the minimum append-only Supabase migration(s) and trusted operations for owner-validated contextual associations:

- A Page may be linked to an owned Quest with optional `MAP`, `EXPLORE`, or `CRAFT` stage context and an explicitly bounded relationship such as `REFERENCE` / `CREATED_DURING` / `APPLIES_TO`. A Quest's Journey is located through the owned Quest identity; do **not** create a parallel Journey-owned document.
- Support an optional link from an owned Page to an already-existing owned practice Session, without creating a new Session or changing session history. A Session link must not imply achievement or practice time.
- Preserve an unassociated page path and multiple distinct links where meaningful. Prevent duplicate equivalent links, cross-Player links, mismatched workbook/page IDs, unsupported stage values, and orphaned context rows.
- Use the JRN-000 optional association contract as the baseline. A page-granular Quest link may be used because Map/Explore/Craft entries can target different pages; document any schema adjustment without changing ownership.
- Quest deletion and Session deletion cascade **only** their association rows; Page/Workbook deletion cascades the corresponding link rows. Account deletion must remove all owned data. Avoid any link FK / trigger that defeats the existing attempted-Quest deletion protection or auth-account cascade.
- Keep the entire write boundary in narrow `SECURITY DEFINER` RPCs (or an equally trusted existing server boundary): fixed safe search path, `auth.uid()` owner derivation, strict identity validation, bounded inputs, limited EXECUTE grants, and read-only owner-scoped RLS. No client-submitted owner, direct table mutation, or service-role browser use.
- Avoid changing page document revision on linking/unlinking unless an accepted authority explicitly requires it. Existing page autosave conflicts must remain correct.

### B. MEC Journey contextual entry points

In the existing Journey UI, add compact, accessible, stage-specific Workbook affordances. They must not crowd or replace Map content, Explore practice guidance, Craft ingredients, or Start Practice:

- **Map:** optional notes / references to prepare a Quest; no compulsory worksheet or Session.
- **Explore:** accessible entry to an associated observation page or creation/linking of a new observation.
- **Craft:** accessible entry to a persistent composition page using the existing rich-text, tablature, and chord blocks; replace the obsolete claim that Craft cannot save artifacts with accurate copy.
- Show existing linked page names and a clear means to open them, plus an explicit action to create a linked page or associate an existing Player-owned page. Do not silently force one Workbook per Quest; a Player can choose existing Workbook/Quick Notes or a newly created Workbook.
- Links must be discoverable on revisiting stages, refresh, and later sign-in. A page may be revisited from the standalone `/workbooks` Library independently of its Quest.

### C. Shared editor contextual workflow

Reuse `/workbooks` and `WorkbookPersistenceSurface` as the sole editor; support a validated internal Quest/stage/page context or a dedicated safe equivalent:

- Provide unambiguous context (Quest title, stage, link status) and a **Return to Journey** action; avoid unsafe open redirects. Standalone visits remain unchanged.
- Explicitly link/unlink the current page, or create a new page and link it to the selected Quest/stage only after a successful trusted operation. Make failures visible and recoverable; never claim “linked” before server acceptance.
- Preserve accepted content and local pending/conflicting drafts on page/Workbook navigation. Existing pending-save navigation protection must also cover contextual return/open/create flows.
- Ensure archived/missing/unowned Quest/Page references degrade safely: no cross-owner information, no silent deletion, no redirect loop, and no unattached content incorrectly labeled as attached.
- Session association, where exposed, is an explicit attach action for an **existing** owned Session and never an automatic practice timer event. It may be surfaced from Journey recent-Session context without moving the editor into the active Session timer.

### D. Verification and regression

**Database / security:** Add local and linked/staging pgTAP tests (where authorized) for owner success, non-owner / unauthenticated refusal, guest parity, forged Quest/Session/Page/Workbook IDs, RLS + grants, invalid stage/relationship, duplicate attach/idempotent repeat, detach/re-attach, Quest/Session deletion unlink without Page loss, attempted-Quest deletion protection, auth-account cascade, and absence of unauthorized progression writes.

**Application / browser:** Add Vitest and real Playwright journeys:
1. Save Quest → Map → create/link note → return → Explore → link a different page → Craft → save tablature/chord composition → refresh → revisit all three linked pages.
2. Workbook A / Workbook B and Quick Notes retain independent, correct content; existing pages can be linked and unlinked without document rewrite.
3. Accepted page persists after sign-out/sign-in and navigation; conflicting unsaved edits are not overwritten on Return to Journey or context switch.
4. Several Sessions against the same Quest remain unchanged after note creation, linking, and stage switches; Session count, Results, XP, progression, and Journey lifecycle do not inflate.
5. Quest archival/reopen preserves links; ordinary deletion of a deletable Quest removes links only while preserving pages; attempted-Quest deletion remains guarded.
6. Invalid and cross-owner deep links fail safely; guest onboarding and protected Player behavior remain intact.
7. Desktop Chromium/Firefox/WebKit, Pixel 7 Chromium, mobile WebKit, 320px Chromium: keyboard, focus, touch, axe, no page-level horizontal overflow, and existing musical-block geometry and persistence tests.

Require full formatting, lint, strict TypeScript, Vitest, production build, security scan, database contract CI when migration paths change, and final-head UX workflow. If browser OS dependencies fail before tests run, fix CI runner rather than count the unexecuted matrix as PASS.
