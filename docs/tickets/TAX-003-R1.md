# TAX-003-R1 — Canonical Tuning Context Remediation

**Status:** VALIDATING  
**Parent:** TAX-003  
**Blocks:** PLY-002  
**Date:** 2026-09-28

## Defect

TAX-001 explicitly defines Tuning as a canonical Context family and names Standard
Tuning, DADGAD, and Drop D as examples. PLY-001 requires Player tuning preferences to
reference canonical tuning Contexts.

The deployed TAX-003 seed contained style/role/tonal Contexts but no tuning Contexts.

PLY-002 database testing exposed the gap when its RLS test attempted to select
`standard_tuning`; the zero-row SELECT caused the INSERT to become a no-op rather than
exercise the cross-owner RLS policy.

## Remediation

Add three frozen canonical Contexts in a new forward-only migration:

- `standard_tuning`
- `dadgad`
- `drop_d`

Each is marked with:

- `context_family = TUNING`
- six-string count
- low-to-high open-string pitch metadata

Existing TAX-003 IDs and the already-applied migration remain unchanged.

## PLY-002 consequence

PLY-002 tuning/setup validation is strengthened to require both:

- taxonomy kind = `CONTEXT`
- metadata `context_family = TUNING`

A genre or tonal-center Context therefore cannot be stored as a Player tuning.
