# ONB-001-R1 — Authenticated Onboarding Tuning Preference Persistence

**Status:** IN PROGRESS
**Phase:** 2 — Core Quest Loop
**Parent:** ONB-001
**Blocked dependent:** REL-002

## Objective

Repair authenticated onboarding persistence so anonymous and permanent Players can
complete the accepted ONB-001 flow without broadening the PLY-002 table privileges or
leaving a partially completed profile.

## Defect

The browser attempted a PostgREST upsert on `player_tuning_preferences` using the
`(player_id, tuning_context_id)` conflict target. PLY-002 intentionally permits
authenticated INSERT of those columns but UPDATE of only `rank` and `is_default`, so
the generated upsert was denied. The browser also marked onboarding `COMPLETE` before
the required tuning and optional goal writes had succeeded.

## Architecture decision

Use an atomic onboarding-completion RPC. The function derives the Player from
`auth.uid()`, accepts no Player identifier, validates an active canonical TUNING
Context, persists the accepted authored profile fields, changes the one default
tuning safely, de-duplicates an identical active onboarding goal, and marks onboarding
`COMPLETE` in the same transaction.

The boundary is `SECURITY DEFINER` with an empty search path and schema-qualified
objects. Execute is limited to `authenticated` and `service_role`; direct table grants,
RLS, immutable-owner enforcement, and all derived state remain unchanged.

## Scope

- forward-only onboarding persistence migration
- production onboarding integration with the RPC
- focused application and pgTAP coverage
- real anonymous-auth browser acceptance through Generate reachability
- local, CI, and linked staging validation

## Non-goals

No Quest, Session, Result, History, progression, Training, recommendation, P2 gate,
or production-cutover work. REL-002 remains blocked and is not resumed here.
