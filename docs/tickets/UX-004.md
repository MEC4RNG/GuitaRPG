# UX-004 — Launch Surface Truthfulness & Placeholder Cleanup

**Status:** IN PROGRESS

## Objective

Make the existing v1 launch-facing Home, application shell, and primary navigation describe the product that exists now, while removing the exposed placeholder Settings surface and preserving every functional core-loop route.

## Stale-state audit

The Home and shell still exposed Phase 0/1 implementation history, future-tense Quest and Player claims, foundation status language, and production-cutover state. Desktop navigation also exposed a placeholder Settings destination that UX_V1_1 explicitly defers.

## Home changes

- Hero kicker now uses product language: Practice · Progress · Adapt.
- Hero copy describes current generation, Results, evidence, and adaptive practice in present tense.
- Primary actions lead to Generate and Recommended Training.
- Quick Start describes current Quest generation.
- Training explains recommendations using Skill evidence, goals, readiness, and challenge preference.
- Development explains UNRATED Skills, evidence, proficiency, confidence, readiness, and engagement XP without fake ability claims.
- The internal project-status panel is removed; the truthful five-step core-loop signal remains.

## Shell and navigation changes

- AppShell no longer presents `v1 foundation` or a false operational status.
- Sidebar no longer presents a development phase chip or foundation/contract status.
- Sidebar footer uses neutral product language.
- Desktop SYSTEM navigation contains Profile only, matching UX_V1_1.
- Mobile navigation remains Home, Generate, Skills, Profile.
- Unused Settings navigation icon semantics are removed.

## Settings route disposition

The placeholder `/settings` page is removed without redirecting to Profile or inventing replacement Settings behavior. A future independently meaningful Settings capability may reintroduce the route and navigation through its own authority.

## Explicit non-goals

No Profile editing, Codex implementation, Settings behavior, broad redesign, database change, migration, dependency-infrastructure change, Phase 5 integration work, gate work, or production cutover is included. PLY-003 remains unauthorized.

## Desktop, mobile, and accessibility evidence

Desktop Chromium passed 5/5 browser tests. Pixel 7 passed 3/3 browser tests. Together they cover truthful Home rendering, functional Generate and Training entry points, exact persistent navigation exposure, no Settings exposure, Codex/Profile visibility where specified, no horizontal overflow, onboarding, Quest generation, session completion, and Training target selection. The implementation retains semantic headings, descriptive actions, skip navigation, focus behavior, touch-target rules, reduced-motion behavior, and color-independent meaning.
