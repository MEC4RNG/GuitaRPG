## Data model

Public read-only:

- `public.taxonomy_entities`
- `public.taxonomy_relationships`

Private migration provenance:

- `private.taxonomy_legacy_mappings`
- `private.taxonomy_legacy_mapping_targets`

Ordinary `anon` and `authenticated` clients receive SELECT only on the public
canonical tables. No ordinary client write policy is created.

## Relationship authority

TAX-003 seeds only relationships already justified by accepted contracts/data:

- each Skill receives one `BELONGS_TO` Domain edge

It does **not** invent:

- `SUBSKILL_OF`
- `REQUIRES`
- `SUPPORTS`
- `RELATED_TO`
- `AFFECTS` weights/edges

The schema validates those relationship types for later migrations, but future semantic
edges require their own accepted evidence.

## Stable identity

TAX-003 freezes the initial UUIDs in:

`domain/taxonomy/canonical-taxonomy.json`

Future migrations must preserve existing IDs/slugs. New taxonomy entities receive new
IDs; the initial catalog must never be renumbered.

## Parameterized legacy mappings

Legacy parameter values remain provenance on mapping targets rather than becoming
duplicate canonical entities.

Examples:

- A through G#/Ab map to canonical Context `tonal_center` with pitch-class parameters
- Two Strings for Chords maps to Constraint `string_count` with `count=2`

## Non-goals

TAX-003 does not implement:

- Player proficiency or evidence
- Quest difficulty
- XP or Attributes progression
- Codex article content
- recommendation scoring
- exhaustive prerequisite graph
- Skill-to-Attribute weights
- user-created taxonomy
- Player-owned tables
