# QST-004 — Quest-to-Codex Reference Integration

**Status:** COMPLETE

## Objective

Derive verified CODEX-001 links from canonical references already embedded in generated, Training, and persisted Session Quest snapshots without changing Quest semantics or persistence.

## Boundaries

Quest snapshot names remain historical presentation authority. The resolver verifies current active Codex availability, falls back to plain text, and keeps pitch classes and parameterized constraint values separate from their reusable Codex definitions. No taxonomy, Codex content, database, generation, recommendation, History, or progression behavior changes.

## Canonical reference mapping

`lib/quest/codex-references.ts` maps Primary/Secondary/Required-Technique Skills, Concepts, Constraints, and embedded Contexts through the active CODEX-001 catalog. Snapshot names remain presentation authority, while current entry existence alone determines whether a link is emitted. Missing entries fall back to plain text.

Tonal Center links the reusable Context definition while retaining the Quest pitch class as a parameter. Constraint definitions likewise remain separate from BPM, string, fret, duration, and other Quest-specific values.

## Surface integration

Generate and Training previews share compact reference components without changing generation, recommendation, adaptation, or Start Practice behavior. Session reads and parses the owning Quest's immutable `resolved_snapshot`, replacing opaque execution JSON with Primary Skill, Concepts, Constraints, Context, and objective information while retaining all practice controls.
