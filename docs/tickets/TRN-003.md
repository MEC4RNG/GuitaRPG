# TRN-003 — Training Surface Integration

**Status:** IN PROGRESS

## Objective

Replace the `/training` placeholder with the first adaptive Training experience by composing the accepted TRN_CAND_V1 → TRN_SCORE_V1 → QST_GEN_V1 TRAINING → persistence → SES-001 path.

## Recommendation loading and presentation

The client loads only through `readRankedRecommendationsV1`, which refreshes readiness and then composes the accepted candidate and scoring models. A pure presentation model maps component explanation codes to bounded Player-facing copy without recalculating eligibility, intent, score, rank, or top ties.

- A unique top is labelled “Recommended next” and remains changeable.
- Equal top scores remain an explicitly labelled tie; no target is initially selected.
- All eligible candidates remain available in stable dense-rank order through a compact selector and disclosure list.
- Training priority is explicitly described as a comparison of current training signals, not ability or mastery.
- Missing projections and unmapped goals receive non-authoritative notices rather than fabricated recommendations.

## TRN_MAT_V1

`materializeTrainingQuestV1` accepts the immutable ranked snapshot, selected candidate key, and truthful selection mode. It always preserves the selected candidate's Primary Skill, passes default tuning when present, and uses canonical `generateTrainingQuest` without applying typical session duration or challenge preference.

The materialized Quest remains `QST_GEN_V1` / TRAINING with computed DIF_V1 demand. `metadata.training_recommendation` records `TRN_MAT_V1`, candidate/scoring versions, candidate key, evaluation time, dense rank, priority score, top-tie count, selection mode, and the component snapshot. This metadata is explanatory history only and carries no progression authority.

Accepted selection modes are:

- `UNIQUE_TOP_ACCEPTED`
- `TOP_TIE_USER_SELECTED`
- `ALTERNATIVE_USER_SELECTED`

Invalid selection-mode/candidate combinations fail closed.

## Quest and Session flow

The Player may rebuild a different concrete Quest for the same selected recommendation without reranking. The preview shows canonical Quest facts and separately explains why the Skill was selected. Start Practice reuses `startGeneratedQuestPractice`; if Session start fails after persistence, the durable Quest ID is retained and retry skips duplicate persistence.

Refresh Recommendations explicitly rereads readiness and ranking and discards an unpersisted preview. Loading and failure states never display a stale ranking as current.

## New-Player and fixture truthfulness

- Healthy new Player: 15 candidates, all priority `54.00`, all semantic rank 1, no fake winner, explicit selection required.
- Exact Skill goal fixture: priority `74.00`, truthful unique top.
- Domain-goal fixture: capable Domain Skills priority `64.00`, tied and unselected.
- DORIAN fixture: Hybrid Picking `47.36` above Scale Mapping and Syncopation Control at `43.00`.

## Accessibility and mobile

The surface uses semantic headings, a labelled native select, keyboard-operable disclosures, native buttons, status/error roles, visible text labels, disabled states, and existing 44px touch targets. Desktop Chrome and Pixel 7 both complete the Training journey without horizontal overflow or bottom-navigation obstruction.
