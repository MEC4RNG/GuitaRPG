### 2. Craft composition usability defects and layout

- **Pointer affordance defect (user-reported):** Mouse pointer does not change to an interactive cursor over Craft composition choices. Investigate buttons, selectors, page actions, menu controls, and enabled vs disabled states; correct actual clickable affordances, preserve keyboard/touch focus and semantic interaction. Existing CSS applies `cursor: pointer` under `.workbook-library button:not(:disabled)`, but embedded Craft uses `.craft-workspace` without `.workbook-library` ancestor — a **candidate styling scope cause**, not yet a browser-confirmed root cause. Check all relevant controls rather than just one selector.
- **Spacing:** The Craft controls/labels/items are crowded; increase clear visual separation between major groups and improve rhythm within the editor toolbar, page selector, and composition actions, while avoiding unnecessary whitespace.
- **Left side of composition editor:** Page/workbook navigation and associated controls feel confusing. Audit duplication between the embedded Craft selector and the underlying `WorkbookEditorPrototype` pages/navigation. Rationalize to **one clear active-composition navigation hierarchy**, with obvious selected state and actions, without removing functional page management or confusing cross-Workbook ownership.

Remove or consolidate repeated decorative/instructional copy; **never remove required autosave/conflict/error/recovery, authentication/privacy, archival, evidence/non-grading, or accessibility information**. Prefer concise disclosure or quiet status UI for essential secondary information.
- Preserve the embedded persistent document authority (Tiptap, tab/chord blocks, accepted revisions, autosave, conflict protection) and `Open in Full Workbook Editor` behavior. Do not introduce an editor fork or a second document store.

**Source observations:** `components/workbook-persistence-surface.tsx` embedded Craft header/action/selector around lines 339–421; it mounts `WorkbookEditorPrototype` below. `components/workbook-editor-prototype.tsx` has its own title, page strip, actions and save status near lines 1380–1515; these may cause density/duplication. `app/globals.css` has the `.craft-workspace` and scoped pointer selectors.

## Proposed acceptance criteria (draft, subject to remaining feedback)

1. Quest header clearly prioritizes title and compact metadata values; visible repetitive labels are reduced, semantics stay accessible, and no information is lost or misrepresented.
2. Quest challenge/parameter presentation exposes **all applicable actual** immutable-snapshot challenges, preserves restrictive non-Codex information, links only verified canonical references, and handles empty/varied Quest types gracefully.
3. Title/objective hierarchy is legible on desktop and 320px mobile without relying solely on colors or icons; final graphic treatment remains deferred.
4. Every enabled actionable Craft control has visibly interactive hover/pointer, focus, and touch affordances; disabled elements do not misleadingly appear active.
5. Embedded Craft presents a clear singular page/workbook navigation hierarchy and comfortable spacing. The exact selected page and owning Workbook are always clear.
6. Autosave status, unresolved conflicts and retry, recovery history, protected/guest account warnings, truthful no-grading statements, and keyboard/screen-reader labels remain accessible even if decorative copy is reduced.
7. Map/Explore/Craft integrations, composition latest-edit selection, multi-page persistence, owner validation/RLS, Quest/context associations, Sessions/Results/XP/progression, Codex Peek, responsive musical geometry, and standalone `/workbooks` do not regress.
8. Any eventual implementation requires desktop/mobile interactive re-review plus refreshed final-head Vitest, pgTAP if data paths change, browser+axe, build, lint/typecheck, security/CI evidence. Do not claim existing final-head CI still applies after a new code commit.

## 2026-11-13 — Map objective-driven learning workflow (second review installment)

**Source:** User's continued interactive visual review; design direction recorded, not frozen or implementation-authorized. The user still intends to review the rest of Map/Explore/Craft.

### User requests, in priority order

1. **Quest header / main Quest information:** Once the objective(s) and parameters/challenges have been moved into the main Quest box (per first R2 feedback), make the relevant items **selectable**. Selecting an objective or appropriate Skill/concept challenge should change designated **Map information regions** to show learning material about that selected item. Where applicable, derive content from official Codex; do not treat restrictive Challenge constraints or numeric targets as automatically having a Codex article.
2. **Map content depth:** Current Codex is relatively compact and may need major enrichment to make Map useful. Plan for deeper official learning material, but keep content authority/versioning separate from the Player's personal Workbook.
3. **New Workbook from Map:** Place **New Workbook** in the selected objective's main Map information area. On explicit click, create a Player-owned Workbook with an initial Page 1 prepopulated with relevant selected objective/official reference material, preserving a clear distinction between imported reference and editable Player content. Link the new page to the current Quest and its selected Explore module where valid. Transition deliberately into **Explore with that module expanded and the newly created Workbook/page open**. This means Explore needs a clear inline/opened-page experience, not merely navigation to standalone `/workbooks`.
4. **Map side panel:** Move the Map's existing **Notes and references / linked Workbook pages** panel out of the main Map canvas into the current right-side **Practice This Journey** slot. Remove that redundant practice sidebar framing.
5. **Start Practice:** Move the practice action to a shared Quest header location across **all three MEC stages**, or consider an unobtrusive floating/sticky action to free the sidebar. This is an **open placement decision**; the primary requirement is persistent accessibility and avoidance of obstruction. The current session lifecycle and `Start Quest` versus `Start Practice` semantics must remain intact.

### Architecture and interface notes (proposal, not final design)

- **Map selection is presentation state**, not a Quest edit, evidence claim, or Journey-stage transition. The selected item's source identity (Skill/Concept/Context/Constraint vs objective criterion) must be explicit. Some objective criteria are numeric/boolean and have **no** corresponding Codex entry. Map must not invent a lesson for them.
- **Proposed Map detail regions:** (a) **What it is** — versioned Codex definition/lesson if available, (b) **How it relates to this Quest** — actual immutable objective, criterion, role, context, or restriction; (c) **Explore / practice guidance** — curated instructional examples only when backed by content. Show truthful sparse/empty states when material isn't authored. Retain non-Codex challenge facts.
- **Codex enrichment dependency:** Existing `CODEX_CONTENT_V1` is definition-oriented. Rich diagrams, structured examples, exercise steps, and citations may require a separately approved Codex content/schema workstream. The Map selection mechanism can be built against existing content without claiming the enriched corpus exists. Do not silently expand all Codex entries within JRN-004-R2 or conflate the deferred JRN-005 personal-content association work with official curriculum enrichment.
- **New Workbook bootstrap:** Preserve JRN-000 ownership/revision/integrity. A generated seed page should identify the selected Quest objective/reference and reference version, show clearly what is official reference vs Player-editable notes, and remain Player-owned if the association or Explore transition fails. Never reparent system-owned Codex content into canonical authority or imply that future Codex changes silently update the Player's historical pages. Design trusted create+seed+link behavior for recoverable partial failures and no duplicate Workbook on retry.
- **Explore handoff:** On successful create, navigate to Explore with intended module and page selected; stage transition is an explicit result of this click, not side effect of merely opening/reading Map. Use the existing module-identity link boundary; avoid a new Quest-owned document system. If no canonical module corresponds to the selected objective/constraint, define and display a General/Unassigned landing rather than assign arbitrarily.
- **Right-panel composition by stage:** Map → linked Workbook list and create/discovery affordances; Explore → modules in main canvas (possibly compact contextual panel later); Craft → prior approved Quest Toolkit in sidebar. **Global Start Practice** moves outside the panel consistently; do not delete useful Craft Toolkit or Explore guidance while reallocating the Map side panel.
- **Preferred placement to prototype:** Stable, visible header action for Start Practice on desktop; a compact, non-obstructing sticky action on mobile only if needed. A floating button must not cover tab/chord editors, keyboard focus targets, or Map content. This placement is not yet user-approved.
- Avoid embedding two simultaneously active editors for the same page; shared persistent editor must preserve autosave/conflict/draft state across Map → Explore handoff.
