## Objective and boundary

Replace the Character and Skills placeholders with responsive, accessible, read-only Practice Lab views backed by the accepted Phase 3 projection state. UX-003 does not change database schema, progression semantics, correction/recomputation operations, recommendations, the application shell, or production cutover.

## Character information architecture

- Character Level leads the page and is explicitly described as practice progress rather than overall guitar ability.
- Practice XP shows cumulative XP, XP within the current CHAR_V1 interval, the next threshold, and a labelled progress bar.
- recorded meaningful practice formats `total_practice_seconds` without claiming lifetime playing time
- all 11 Attributes are organized into Physical and Musical groups
- UNASSESSED renders no numeric score; ESTIMATED and ESTABLISHED render their score with a visible qualifier
- the zero-XP/new-Player state offers a factual Generate a Quest action without sample progress

## Skills information architecture

- all 72 active canonical Skills appear exactly once under their BELONGS_TO Domain
- collapsed rows expose name, Domain, assessment status, visible Level when rated, and readiness
- semantic disclosure details expose proficiency, system confidence, readiness score, exposure, evidence, and recency separately
- search, canonical Domain filtering, and assessment-status filtering operate over a deterministic established → estimated → unrated, then alphabetical order
- an unexpected missing projection renders UNAVAILABLE and explicitly refuses to coerce the Skill to Level I

## Read-model architecture

`lib/progression/read-model.ts` owns pure CHAR_V1 presentation calculations, taxonomy/state assembly, grouping, filtering, deterministic ordering, duration, and recency formatting. `lib/progression/repository.ts` owns bounded owner-context reads.

Character uses three parallel reads: Character projection, Attribute projections, and active Attribute taxonomy. Skills calls `refresh_player_readiness()` exactly once, then uses four batched reads for active Skills, Domains, BELONGS_TO relationships, and Skill projections. Neither path performs per-entity reads or browser progression mutations. A refresh failure retains the Skill projection but displays a non-blocking stale-readiness notice.

## Semantic safeguards

- Practice XP remains engagement/effort, not ability
- Attributes remain distinct from Skill Levels and XP
- UNASSESSED and UNRATED never render as numeric zero or Level I
- ESTIMATED remains visibly distinct from ESTABLISHED
- proficiency, confidence, readiness, exposure, and evidence remain distinct
- no overall guitarist rating or recommendation logic

## Mobile and accessibility

- semantic headings, labelled native controls, keyboard-operable details, visible focus, and live status/error messaging
- status and readiness always include text; color is supplemental
- compact mobile Skill summaries expose assessment and readiness before expansion
- Pixel 7 Skills and direct Character routes pass without horizontal overflow or bottom-navigation obstruction
- loading does not flash fake zeros; recoverable failures include Retry
