# QST-001 — Canonical Quest Contract

**Status:** COMPLETE  
**Date:** 2026-09-27  
**Authority:** Phase 0 — Architecture & Contracts

## Objective

Define the canonical structured Quest object that connects taxonomy and Player state to generation, practice sessions, difficulty, evidence, progression, recommendations, and history.

## Result

The Quest contract now defines:

- five Quest Types
- identity/versioning
- purpose and generation mode
- exactly one Primary Skill
- 0–2 Secondary Skills
- Required Technique Skill roles
- Concepts
- Context
- 1–3 normal Constraints
- execution parameters
- machine-readable Objective criteria
- Completion Contract
- Verification Profile
- Difficulty container
- Rewards container
- immutable Quest/session/result boundary

Critical rule:

A Quest is a practice plan. It does not embed the attempt outcome, verification evidence, reflection, XP, or proficiency mutation.
