## Objective

Persist the accepted JRN-001 `GUITARPG_WORKBOOK_DOCUMENT_V1` editor as private Player-owned Workbooks with multiple pages, autosave, optimistic concurrency, recovery revisions, Quick Notes, archive/restore, and cross-device retrieval.

## Implementation decisions

- Ownership is `auth.uid()` → Workbook → Page → immutable accepted snapshots. No Quest, Session, Result, or progression relationship exists in JRN-002.
- Migration: `20261017020000_jrn_002_workbook_persistence.sql`.
- Tables: `player_workbooks`, `player_workbook_pages`, and `player_workbook_page_revisions`.
- Ordinary authenticated clients receive owner-scoped `SELECT` only. All mutations cross narrow `SECURITY DEFINER` RPCs with an empty search path.
- `WORKBOOK` and `QUICK_NOTES` are the only V1 kinds. A partial unique index permits one Quick Notes Workbook per Player; the trusted operation safely locates or creates it.
- Integer page positions are transactionally reordered. A Workbook always retains at least one page.
- A page save supplies its expected revision and a stable request UUID. The page row is locked, stale revisions return a conflict without mutation, and repeat delivery of one request UUID returns the previously accepted revision.
- Restoring a retained snapshot creates a new accepted revision. Accepted revision rows are update-immutable.
- The newest 50 accepted snapshots per page are retained, including the current revision. This bounds autosave growth while guaranteeing recovery to any of the last 49 prior accepted states.
- Document limit: 512 KiB serialized JSON; 200 blocks; 32 KiB paragraph/heading content; 100 list items/64 KiB per list; 512 events per tab block and 2,048 tab events per page; six notes per event; frets 0–36; six-string Standard or DADGAD tuning; six chord strings and six barres.
- Autosave debounces for 900 ms and displays Unsaved changes, Saving, Saved, Save failed, or Conflict only from real state. Pending edits trigger browser navigation protection. Conflict leaves the local document intact for JSON copy/export or explicit reload/reconciliation.
- Browser storage is not used for private document buffering in V1. Pending state is memory-only and is cleared naturally on sign-out/account switch; unload is never claimed as a guaranteed save.
- `/workbooks` is preview/development-only through the production `notFound()` gate and is intentionally absent from production navigation.

## Export and deletion compatibility receipt for DATA-005

Auth-user deletion cascades Workbooks, Pages, and Revisions. Deleting a Workbook cascades its Page graph. Existing Player export V1 is deliberately unchanged and does **not** claim Workbook coverage; the Workbook surface states this limitation and offers per-page document JSON. DATA-005 must add all three datasets (or a stable Workbook aggregate) to a new versioned export contract and retain document schema/revision metadata. Creation, modification, revision, practice, and Session dates remain semantically distinct.

## JRN-002-R1 — Workbook page persistence and library UX remediation

User review confirmed authentication/recovery, Workbook creation, initial persistence, refresh persistence, and sign-out/sign-in persistence. It also found three defects: additional pages disappeared after changing Workbooks, archived Quick Notes did not expose the individual note title, and Library actions lacked consistent desktop pointer affordance.

- Root cause: page create, duplicate, delete, reorder, and accepted saves updated only `WorkbookEditorPrototype` state. `WorkbookPersistenceSurface` retained its original Supabase hydration snapshot, so remounting the editor reconstructed the Workbook from stale parent state even though the accepted page rows existed in the database.
- Correction: every accepted page mutation now updates the parent server-authoritative page collection. Accepted saves replace the matching parent page with the returned server row, including title, document, and revision token. Page switches synchronously update the editor page ref so the newly selected page cannot inherit the preceding page's document.
- Pending-save safety: cross-Workbook selection, Workbook creation, Quick Note creation, and archive of the selected Workbook are refused while local edits remain unacknowledged. Navigation becomes available after the server reports `Saved`; the existing unload warning and conflict preservation remain intact.
- Quick Notes: the singleton `QUICK_NOTES` architecture is unchanged. Archived Quick Notes now list their accepted page titles beneath the Workbook label, and archive/restore does not rewrite page title or ownership.
- Pointer affordance: enabled Workbook Library and revision actions use `cursor: pointer`; disabled semantic buttons retain `cursor: not-allowed` and existing keyboard focus behavior.
- Regression: the exact Workbook A → three accepted titled pages → Workbook B → Workbook A journey passes, including unique page content and full refresh. Reorder persists across refresh; duplicate/delete remains durable; pending navigation is protected; two-Workbook state remains isolated; archived Quick Note titles remain visible; stale cross-device writes remain conflicts.
- Browser validation: desktop Chromium 5/5 PASS. Pixel 7 Chromium, desktop WebKit, 320 px Chromium, and mobile WebKit 20/20 PASS. Axe and horizontal-overflow checks remain included. Firefox remains assigned to supported CI because the local Windows runtime is unavailable.
- Application validation: full Vitest 84 files / 519 tests PASS; ESLint, strict TypeScript, production build, formatting, and browser secret scan PASS. No migration or database contract changed; the established local and linked 21-file / 726-assertion pgTAP evidence remains applicable.
- User acceptance remains pending on the refreshed Preview. PR #10 remains draft, open, and unmerged.

## JRN-002-R2 — Workbook page navigation and organization UX refinement

User interactive review confirmed that multi-page Workbook content now persists through navigation, refresh, and sign-in/out. One remaining design issue was identified: prominent left/right reorder controls alongside every page title obscured page selection, especially on mobile.

- Page selectors now display concise positional numbers without embedding persistent reorder buttons; a current `Page N of M` indicator provides orientation.
- The same `Page actions` toggle is available on desktop and mobile. Its contextual panel contains `Move page earlier` and `Move page later` for persistent Workbooks, followed by `Duplicate page` and `Delete page`. Actions target the selected page, with invalid boundary moves disabled.
- The panel closes on page selection, after actions, on outside pointer interaction, or on Escape (returning keyboard focus to the toggle). Semantic buttons, keyboard operation, visible focus, and touch targets are retained.
- Reordering still uses the existing trusted reorder RPC and R1 parent/child synchronization; no schema, persistence contract, account identity, MEC behavior, or production route changes.
- Updated the Playwright Workbook navigation regression to cover concise selectors, current page position, responsive Page actions, first-page disabled move, Escape behavior, duplicate/delete, and accepted order after refresh.
- Status: user approved the updated Workbook experience on 2026-11-06 and authorized JRN-002 closeout. Required final-head CI remains the merge gate. JRN-003 is **not** authorized.
