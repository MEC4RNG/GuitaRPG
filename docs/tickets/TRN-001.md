# TRN-001 — Recommendation Candidate Generation

**Status:** IN PROGRESS

## Objective

Define `TRN_CAND_V1`, an ephemeral and deterministic inventory of canonical generator-capable Primary Skills with truthful Player-state and structured-goal signals. The model produces candidates, not rankings, winners, recommendations, persisted Quests, or Player-facing Training copy.

## Scope boundary

No database migration, candidate persistence, recommendation scoring/ranking, Training UI, automatic selection, personal difficulty assignment, or Quest persistence is authorized. TRN-002 and TRN-003 remain unauthorized.

## Candidate model

`TRN_CAND_V1` returns an ephemeral `RecommendationCandidateSetV1` with explicit evaluation time, `QST_GEN_V1`, `QST_GEN_RULES_V1`, and `STABLE_NOT_RANKED` ordering. Candidate keys are `TRN_CAND_V1:<primary-skill-slug>`. Capability is derived from the real generator templates in canonical Domain order and then Skill slug; duplicate Primary template coverage is diagnosed rather than emitted as duplicate candidate identity.

Each candidate contains a read-only Skill projection snapshot, canonical Domain, generator template, supported Quest Types, template purpose, available Concepts, permitted supporting roles, allowed Constraints, factual reasons, and structured goal matches with raw existing priority. It contains no recommendation score, rank, winner, selection, personal difficulty, XP, Character Level, or Attribute input.

## Eligibility and intents

Eligibility requires an ACTIVE canonical SKILL, live QST_GEN_V1 Primary capability, a valid template, and an existing Player Skill projection. Missing projections are omitted and reported as `MISSING_PLAYER_SKILL_STATE`; no synthetic UNRATED or Level I state is created.

- UNRATED → CALIBRATION
- rated LOW readiness → REFRESH
- ESTIMATED non-LOW → DEVELOPMENT
- ESTABLISHED non-LOW → MAINTENANCE

MODERATE readiness is carried as a factual signal and does not force REFRESH. Confidence below the accepted establishment threshold of 60 is carried as a factual reason only.

## Snapshot repository

The bounded repository calls ordinary-owner `refresh_player_readiness()` once before any reads and fails closed when refresh fails. It then loads profile context, active goals, default tuning preference, Skill projections, and active taxonomy in bounded parallel queries. Challenge preference, typical session duration, and default tuning are carried without affecting eligibility, intent, composition, or ordering. No data is written.

## Goal behavior

Exact structured Skill goals add `GOAL_SKILL_MATCH`; exact structured Domain goals annotate every capable candidate in that Domain with `GOAL_DOMAIN_MATCH`. Raw goal priority is retained but never used for order. Free-text-only goals are not interpreted and become `UNPARSED_OBJECTIVE_GOAL` diagnostics. Structured goals targeting canonical Skills outside current Primary generator coverage become `UNSUPPORTED_GOAL_SKILL`; no substitute is invented.

## Generator coverage and diagnostics

The current catalog deterministically resolves 15 unique Primary-capable Skills across all six canonical Domains. Every capability is an ACTIVE canonical Skill with exactly one template, and every one instantiates a parseable DIF_V1 Custom Quest in tests. The healthy new-Player snapshot contains 72 active Skills, 15 candidates, 57 Skills outside current Primary generator coverage, and zero missing projections. Those 57 remain valid canonical Skills; they are not labelled weak, invalid, or unimportant.

## DORIAN example

Post-DORIAN Hybrid Picking is DEVELOPMENT with `PRIMARY_ESTIMATED`, `READINESS_HIGH`, and `CONFIDENCE_BELOW_ESTABLISHMENT_THRESHOLD`. Scale Mapping and Syncopation Control remain CALIBRATION from their truthful UNRATED projections. No relative rank or recommendation is assigned.

## Deferred scoring and product work

TRN-002 owns weighting, scoring, ranking, challenge-preference effects, weakness/novelty balancing, and concrete Quest-variant evaluation. TRN-003 owns the Training surface and Player-facing explanation. `/training` remains the existing `FoundationPage` placeholder.
