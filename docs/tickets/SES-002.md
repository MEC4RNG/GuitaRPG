## Objective

Implement the Instrument HUD Session surface: a SES-001-derived timer, Web
Audio metronome, durable append-only repetition/BPM control telemetry, and a
structured Quest reference. This ticket does not implement Results, Evidence,
XP, progression, audio input, or recommendations.

## Authority

SES-001 remains authoritative for ACTIVE/PAUSED/ENDED lifecycle state and
recorded active time. SES-002 may add only protected, owner-isolated,
server-timestamped and Session-ordered control telemetry. EVD-002 remains
unauthorized.

## Accepted implementation

`20260929000000_ses_002_practice_controls.sql` adds a separate, append-only
`practice_session_control_events` table with per-Session order, server-authored
timestamps, owner-only reads, account-deletion-safe cascade behavior, and no direct
authenticated writes. Protected rep and BPM RPCs lock the parent Session, require the
authenticated owner and ACTIVE status, prevent a negative derived rep count, and accept
only whole BPM values from 30 through 240.

The `/session/[sessionId]` Instrument HUD uses the SES-001 lifecycle RPC adapter and
event-derived timer. It treats rep/BPM telemetry as a separate SES-002 concern, refreshes
the authoritative Session and telemetry after every RPC success or failure, and never
persists metronome playback state. The Web Audio metronome restarts stopped after reload
and stops for pause/end. No Result, Evidence, XP, progression, audio capture, or
recommendation behavior was introduced.
